HTTP Multiplexing Timeline

Each bar is one HTTP transfer, placed where it actually happened in time and split into the phases curl measured. Bars are grouped into lanes by TCP connection. HTTP/1.1 and HTTP/2 share a time axis in every demo, so the shape of the difference is the point.

How to read it

  • A. HTTP/1.1 needs one lane per concurrent request and pays a TCP connect and TLS handshake in each. HTTP/2 runs every request in one lane and pays the handshake once.
  • B. Browsers allow about six HTTP/1.1 connections per host. With eight requests, two must wait for a lane to free up, and when they do, that lane is reused (no connect or TLS segment on the second bar). On HTTP/2, all eight start together in the one lane.
  • C. On a single HTTP/1.1 connection, the fast request cannot start until the slow response has finished: head-of-line blocking. On HTTP/2 the fast stream completes while the slow one is still open.
  • Every Server-Sent Events stream is a response that stays open. On HTTP/1.1 it holds a lane for its whole life; on HTTP/2 it is just one more stream.
